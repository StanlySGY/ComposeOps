## 第一轮已修复

| 问题 | 修复与证据 |
| --- | --- |
| Docker 存储统计失败会隐藏成功取得的 CPU/内存 | 监控页分别处理两个请求的结果，失败项显示具体提示；回归测试已复现修复前失败 |
| 偏好加载失败导致监控停止初始化 | 能力、偏好加载允许独立失败，使用默认刷新周期继续显示指标 |
| 加载中离开监控页或进入历史标签后重新启动后台轮询 | 轮询由挂载状态、标签、自动刷新开关共同控制；迟到响应通过请求序号丢弃 |
| 关闭自动刷新后往返历史标签又被自动开启 | 保留用户选择，切回实时页只补一次数据 |
| 节点切换遇到在途请求时继续显示旧节点数据 | 监控、总览和项目列表清除旧数据并发起新请求，旧响应不能覆盖新结果；Header 项目操作也同步清场 |
| 缺失总览指标被显示为 0% 和“运行正常” | 显示“— / 暂无指标”，并明确标注为环境 CPU/内存 |
| 没有 Compose 项目时总览连环境指标也隐藏 | 保留指标，空状态提供服务列表、应用市场入口 |
| 强制刷新不更新缓存，下一次读取又退回旧数据 | 强刷替换缓存；首轮请求及后台刷新用缓存条目身份校验，失效后不能复活旧条目 |
| 请求乱序覆盖项目列表 | 只提交最新请求的结果；切换节点立即清除项目列表和更新时间 |
| WebSocket 空快照无法清除已删除项目 | 接受合法空快照；后端读取失败仍是独立 error 帧 |
| Ctrl/Cmd+K 打开后无法可靠关闭 | 移除子组件与 Header 重复的快捷键处理，只保留 Header 切换入口 |
| 命令选中项移出可视区、鼠标悬停抢走键盘选择 | 选中项自动滚入视野；只在鼠标实际移动时切换选择 |

附带修正：网络趋势不再把 0 MB/s 抬升为至少 1 MB/s；监控容器趋势移除已消失容器；请求自定义 headers 不再覆盖自动补齐的 Content-Type。

### 真实 Docker 验证

隔离项目 composeops-audit-20260930 使用两个 busybox:1.36 容器（普通/TTY）、无网络、无暴露端口、32MB 内存限制和专用卷。

1. 普通日志正确区分 stdout/stderr 和时间戳；TTY 中文/emoji 不损坏；聚合收到两容器的预期日志。浏览器项目深链能自动连接。
2. WebSocket 打开后立即发送命令与 resize，真实 shell 输出 READY_UTF8_中文、36×120 的 stty size；命令执行而非仅回显；退出关闭连接。
3. 停止测试容器收到 kill/stop/die 事件。
4. 卷备份→下载 gzip→修改源数据→临时卷演练→确认源数据未被演练覆盖→还原 original→删除归档成功。归档和下载均为 146 字节，演练包含 1 个文件。
5. Compose 读取→校验→保存→读取确认→从备份恢复；env 中文读写；API stop/up/restart 退出码均为 0，接口状态与两容器实际状态分别一致为 stopped/running/running。
6. docker compose down -v 清理测试资源，按专用 Compose 标签查询容器和卷均为空；备份 helper/演练卷此前也已清理。没有更改正式数据库、现有业务容器或生产端口配置。
