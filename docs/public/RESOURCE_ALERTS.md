# 容器资源告警与自动动作

历史指标页可以为纳管容器配置 CPU、内存或重启次数规则。规则使用精确容器 ID；容器重建后，需要为新容器重新配置。项目与服务名称不能用子串匹配扩大范围。连续两个有效超限样本触发一次事件，连续两个正常样本结束事件。缺失、无效或间隔过长的采样打断连续计数，不当作恢复正常。

默认仅通知。开启自动动作需要在表单明确确认，或者在 Agent 的工具确认中审阅 `confirmAutomatic: true` 与对应限制：

- 授权有效期为 7 天，固定项目、节点连接修订、Docker Engine 与当前容器 ID。
- 同一项目的全部资源告警共用 10 分钟冷却，以及滚动 24 小时最多 3 次的自动动作预算。删除、重建规则或重启面板不会重置预算。
- 项目取消纳管、标为维护中或计划停机、节点或规则变化、命中持久拒绝策略时暂停。取得项目操作锁后和发出动作前都会复核；最新指标已恢复时取消本次动作。
- 通知渠道与自动授权独立。关闭通知渠道不会撤销自动动作；需要删除规则或将项目标为维护中。
- 旧规则没有固定目标与期限时继续通知，自动动作暂停。页面显示重新确认说明，不自动迁移授权。

自动重启只处理触发告警的固定容器，检查启动时间是否改变、容器是否运行及现有健康检查是否通过。容器层验收不等于业务 HTTP、SQL 或数据一致性验收。

自动扩容每次增加一个副本，最多 5 个副本；仅支持镜像固定为摘要、无挂载、无固定宿主端口且没有特权或特殊网络的服务。完整 Compose 与环境配置的指纹必须仍与授权时一致。命令明确指定服务，并使用 `--no-recreate --no-deps --no-build --pull never`；它不重建已有副本，不启动其它依赖服务，也不拉取新镜像。验收要求原副本仍存在、新副本数量正确且所有副本运行、已有健康检查通过。

执行记录和预算先持久化，再发出动作。超时、断流、执行报错或验收未完成均可能留下实际副作用，因此标记为结果未知，停止后续自动动作，不自动重放。页面提供“人工核对结果”：先检查实际容器、业务及仍在运行的远端操作，再确认解除暂停。这个确认不会重试旧动作或清空预算。结果未核对时不能删除规则来丢弃记录。

后台采样限制并发和单次等待时间；一轮采样不完整会在规则列表显示。Docker 空间使用 Engine 的共享层聚合统计，不能解释成文件系统剩余空间。

隔离验收脚本：`node scripts/resource-alert-acceptance.mjs <本机已存在的 busybox 镜像@sha256:摘要>`。脚本使用临时数据库、无挂载/无对外端口的独立项目，验证重启、扩容、其它服务保持、配置变化拒绝与跨进程冷却，最后清理自建资源。它不会更改生产规则。

边界：文件指纹复核与之后的 Compose 执行不是跨进程文件系统 CAS；Docker 身份复核也不是与远端 Engine 请求原子绑定。远端命令断流不能证明远端进程已停止。需要强业务恢复验收、故障关联和独立探针的场景应使用可靠性中心的应用目标与有界自治流程。
