## 已完成的安全与可靠性改进

- SSH 远程运维支持可选 SHA-256 主机指纹锁定；错误指纹在握手阶段被拒绝。旧节点未配置指纹时为兼容现有部署仍允许连接，建议通过可信渠道核对后补齐。
- Webhook 类通知遇到网络瞬断、限流或服务端 5xx 时进行有界重试；鉴权及其他非重试型 4xx 立即失败，避免无意义重试。
- 本地自动化测试覆盖 SSH 主机指纹验证、TLS CA/客户端证书和多节点故障隔离、通知重试与本机真实 HTTP Webhook 投递、Agent SSE 取消/慢客户端背压、后台任务内存上限、Docker 隔离卷恢复和 SHA-256 内容核验。
- Agent 阈值告警采用两次连续超限采样才进入告警状态，持续超限不重复触发；两次连续正常采样后清除状态并允许下一次事件重新告警。无效采样不改变状态，规则删除、容器停止/移出纳管或告警规则编辑时清理相应状态。
- 2026-10-15 再次运行 `node scripts/container-recovery-smoke.mjs` 通过：临时 Compose 项目注入停止状态，恢复动作退出码 0，容器回到 running；测试项目自动清理。该场景验证实际 Docker 本机容器恢复，不等同于跨主机恢复。
- SQLite 静态加密采用独立只读密钥文件；明文迁移先流式复制到加密临时文件，并在原子替换前核对完整性、迁移版本、关键表行数与外键检查结果。加密备份已恢复到全新数据卷，停机密钥轮换也已验证新密钥成功、旧密钥拒绝。
- 当前已检查的 WSL `opsdash` 容器数据库状态与历史加密报告不一致：`node scripts/database-encryption.js status --db /app/backend/data/opsdash.db` 返回 `status=plaintext`（`encryptedHeader=false`,`keyVerified=false`）；容器没有 `DB_ENCRYPTION_KEY_FILE` 环境项或密钥文件挂载。在当前可访问的仓库/家目录范围内未找到历史加密快照与外置密钥，无法复现此前演练。**因此这个当前运行实例必须按明文数据库管理**；由于缺少可核实密钥和可回退备份，本轮没有迁移约 869 MB 的运行库，也没有重启服务。应先恢复并核验备份/密钥，再用 `docker-compose.encrypted.yml` 执行受控迁移并验证加密状态、健康检查及核心表计数。

## 验证边界

静态预览是交互演示，不能证明真实 AI 修复能力。自动化验收包含实际本机 Redis/PostgreSQL 容器、HTTPS/TLS 与 loopback Webhook，但不等于真实远端主机、第三方平台送达、外部模型驱动修复、所有业务数据库或跨大版本升级已全部验收。当前仍是单管理员工具，不承诺多租户隔离或零停机升级。
