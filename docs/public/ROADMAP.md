# Public Roadmap

## 1.5.0 的交付范围

- 多渠道故障切换、单渠道保存、密钥按需查看与工具兼容性测试。
- 可重新打开的入门指南、可折叠导航与离线交互预览。
- 发布前必须通过代码检查、浏览器预览检查与隔离镜像安装/升级/恢复检查。
- SQLite 在线一致性备份；应用数据卷仍需按数据库类型制定备份策略。

## 已完成的安全与可靠性改进

- SSH 远程运维支持可选 SHA-256 主机指纹锁定；错误指纹在握手阶段被拒绝。旧节点未配置指纹时为兼容现有部署仍允许连接，建议通过可信渠道核对后补齐。
- Webhook 类通知遇到网络瞬断、限流或服务端 5xx 时进行有界重试；鉴权及其他非重试型 4xx 立即失败，避免无意义重试。
- 本地自动化测试覆盖 SSH 主机指纹验证、TLS CA/客户端证书和多节点故障隔离、通知重试与本机真实 HTTP Webhook 投递、Agent SSE 取消/慢客户端背压、后台任务内存上限、Docker 隔离卷恢复和 SHA-256 内容核验。
- SQLite 静态加密采用独立只读密钥文件；明文迁移先流式复制到加密临时文件，并在原子替换前核对完整性、迁移版本、关键表行数与外键检查结果。加密备份已恢复到全新数据卷，停机密钥轮换也已验证新密钥成功、旧密钥拒绝。
- 当前本机运行实例已启用数据库静态加密；重启后健康检查通过，schema 版本与迁移前关键表行数一致。保留了权限受限的独立加密前快照作回退依据。新装默认仍兼容明文安装，加密启用步骤见《SQLite 数据库静态加密》。

## 下一步，以证据验收

- 生产密钥的异地独立保管与恢复演练；当前密钥通过主机只读文件挂载，与 Docker 数据卷分离，但尚未接入独立 KMS/密钥管理服务。
- 真实远程多主机 SSH/TLS 部署矩阵：节点证书签发/轮换、真实 WAN 断线/重连、服务端证书更新与不同权限账号；本地多节点假服务验证不替代实际部署验收。
- 第三方通知渠道实际送达及平台限流策略：本地 HTTP Webhook 已测试请求体与 503 重试，但尚未用生产渠道凭据验证外部平台最终收件。
- 数小时级持续 Agent 会话/日志跟随/SSE 的 CPU、内存、FD 与慢消费者 soak test；目前已有 5,000 条 SSE、日志字节上限、100 条任务保留量和取消清理回归。
- 真实模型驱动的 Redis/PostgreSQL 根因分析与修复演练：本地自动化已调用真实容器的固定只读健康工具，验证停止、恢复与数据持久化；尚未将实际外部模型接入并执行经过审批的修复链路。
- 更广泛的上游模型兼容性矩阵，以及英文 UI 与键盘/读屏可访问性审计。

## 验证边界

静态预览是交互演示，不能证明真实 AI 修复能力。自动化验收包含实际本机 Redis/PostgreSQL 容器、HTTPS/TLS 与 loopback Webhook，但不等于真实远端主机、第三方平台送达、外部模型驱动修复、所有业务数据库或跨大版本升级已全部验收。当前仍是单管理员工具，不承诺多租户隔离或零停机升级。
