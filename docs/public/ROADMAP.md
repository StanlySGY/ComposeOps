# Public Roadmap

## 1.5.0 的交付范围

- 多渠道故障切换、单渠道保存、密钥按需查看与工具兼容性测试。
- 可重新打开的入门指南、可折叠导航与离线交互预览。
- 发布前必须通过代码检查、浏览器预览检查与隔离镜像安装/升级/恢复检查。
- SQLite 在线一致性备份；应用数据卷仍需按数据库类型制定备份策略。

## 已完成的安全与可靠性改进

- SSH 远程运维支持可选 SHA-256 主机指纹锁定；错误指纹在握手阶段被拒绝。旧节点未配置指纹时为兼容现有部署仍允许连接，建议通过可信渠道核对后补齐。
- Webhook 类通知遇到网络瞬断、限流或服务端 5xx 时进行有界重试；鉴权及其他非重试型 4xx 立即失败，避免无意义重试。
- 本地自动化测试覆盖 SSH 主机指纹验证、TLS CA/客户端证书校验、通知重试与鉴权失败、Agent SSE 取消/审批清理及慢客户端有界缓冲、Docker 隔离卷恢复和内容哈希核验。

## 下一步，以证据验收

- 真实多节点 SSH/TLS 环境矩阵：节点证书签发/轮换、服务端证书错误、断线重连与节点切换隔离；本地假服务测试不能替代实际部署验证。
- 通知渠道真实端到端送达：需要各渠道的测试端点/凭据；自动化目前验证传输重试逻辑，不证明第三方已收到消息。
- 长时间日志流、Agent 会话和后台任务的内存/CPU/文件描述符压力与断线取消回归。
- 更广泛的上游模型兼容性矩阵，以及真实 Redis/PostgreSQL 运维案例的隔离环境演练。
- SQLite 文件本身仍未采用 SQLCipher 等整库静态加密。当前依靠文件权限及凭据脱敏降低暴露面；要完成整库加密还需采用受支持的加密 SQLite 发行版，并设计独立密钥保管、轮换、备份与灾难恢复迁移闭环。
- 英文 UI 与键盘/读屏可访问性审计。

## 验证边界

静态预览是交互演示，不能证明真实 AI 修复能力。隔离自动化测试验证的是本地控制流和假服务行为，不等于真实远端主机、第三方通知渠道、所有业务数据库或跨大版本升级已经验收。当前仍是单管理员工具，不承诺多租户隔离或零停机升级。
