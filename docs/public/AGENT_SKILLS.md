# 本地运维技能

Agent 的 `skill.list` 返回技能名称、简介和来源，`skill.use` 按名称读取一份操作说明。说明作为不可信资料提供给模型，不能扩大工具权限、绕过审批或自动执行其中的命令、脚本与附件。

内置技能在 `backend/src/data/skills/`，自定义技能默认在 `backend/data/skills/`。`AGENT_SKILLS_DIR` 可以指定另一目录；容器部署需要将该目录显式挂载到容器。项目目录不会自动成为技能来源。

每个技能位于独立目录，文件名固定为 `SKILL.md`。目录名和 `name` 必须一致，只允许小写字母、数字、连字符，长度 1–64，首尾不能是连字符。

```markdown
---
name: local-api-check
description: 排查本机 API 服务响应异常，先收集状态与日志证据
---

先确认节点、纳管项目及服务身份，再读取健康状态和近期日志。
结合时间线报告证据；需要重启时仍经过面板的审批流程。
```

`description` 必须为字符串且不超过 1000 个字符，正文必填且最多 20000 个字符。完整文件最多 96 KiB，YAML 头最多 8 KiB。中文正文按字符限制，完整文件按 UTF-8 字节限制。该读取器是 ComposeOps 的受限技能支持，不会执行 Agent Skills 的可选 `allowed-tools` 授权字段。

自定义技能优先覆盖同名内置技能；自定义文件损坏时回落到可读取的内置版本。技能激活按名称读取，不遍历其他技能，下一次激活会读取文件的当前版本。技能根目录、技能目录和文件不能是符号链接，文件不能是硬链接或管道。Linux 部署通过目录句柄固定读取位置，防止读取期间目录被替换后转向另一位置。

目录发现最多返回 100 项，每个根目录最多枚举 2048 项，每次最多尝试读取 256 个技能，保留一部分预算给内置技能。达到返回/扫描上限或目录不能完整读取时，`skill.list` 的 `partial` 为 `true`；`scanned` 为尝试定位的技能数，`skipped` 为读取/格式错误数，不把正常缺失的自定义覆盖项算作损坏。已知名称仍可通过 `skill.use` 定向加载。

发现阶段返回给模型的只有元数据；服务端为保证空正文、错误格式与超长内容不会进入可用目录，对候选文件做有界完整验证，不承诺零正文磁盘读取。不会把所有正文同时保存在目录结果或全局缓存中。
