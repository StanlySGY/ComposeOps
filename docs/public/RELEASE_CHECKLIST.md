# 发布验收与支持范围

面向单用户、个人服务器与自托管部署。以下是每次稳定版必须执行的门禁；具体通过与否以该 tag 对应的 [Release 工作流](https://github.com/StanlySGY/ComposeOps/actions/workflows/release.yml) 为准，历史勾选不代表新版本已经验证。

## 自动发布门禁

| 环节 | 必须满足的条件 |
| --- | --- |
| 版本一致 | Git tag、三个 package.json、根 lockfile、CHANGELOG、安装清单、中英文 README 的版本一致 |
| 代码和浏览器 | 后端串行测试、前端单测、lint、正式/预览构建，以及桌面/手机 Chromium 和 WebKit 交互回归通过 |
| amd64 | 镜像首次安装、鉴权、重启持久化；从 1.4.0 和 1.5.1 升级后可登录并读取原配置 |
| 原生 ARM64 | ubuntu-24.04-arm runner 检查 aarch64，构建镜像、首次安装、从 1.5.1 升级和恢复；不再使用 QEMU 代替该验收 |
| 备份与回退 | 两个架构均执行在线快照、新卷恢复及升级前快照恢复到 1.5.1；amd64 额外保留 1.4.0 回退 |
| 加密 | 两个架构均执行明文到加密迁移、原密码/配置保留、加密快照无明文标记、同一外置密钥在新卷恢复 |
| 实际运维 | 隔离 Redis/PostgreSQL 健康探测和恢复、命名卷备份恢复；amd64 额外执行真实项目浏览器、Compose 多文件回滚及卷恢复失败补偿 |
| 对外发行 | 质量门成功后直接发布导出的已验收镜像，核对镜像 ID、架构与提交 SHA；两架构都上传成功后合并稳定标签，再创建 GitHub Release 和固定版本安装附件 |

Agent deny-first、审批参数重评估、critical 强制确认、并发隔离、审计脱敏、SSE 背压及取消清理由后端回归覆盖。原生 ARM64 云 runner 通过不代表覆盖所有 NAS 型号、内核和存储驱动。

## 发版操作复核

1. 核对固定版本安装命令、升级/回退文档和版本说明，保留已有端口、数据卷和外置密钥。
2. 检查提交内容，确保无真实凭据、会话信息或用户数据库。
3. 核对桌面/手机画面、图像失败兜底、导航返回和键盘焦点；本轮没有 UI 修改时可引用同一产品代码的已存截图及测试。
4. 发布后核对公开镜像 manifest 的两个架构、Release 的 tag/安装附件，以及 Pages 的实际访问和示例数据标识。
5. 需要更新已有实例时，另外执行该实例的备份、健康与数据库检查。隔离候选环境写操作验收不能描述为生产写操作验收。

## 持续验证边界

- 真实 SSH/TLS 远程节点的证书轮换、WAN 断线和跨宿主故障恢复仍需扩大覆盖。
- 真实第三方通知送达与各模型渠道兼容性取决于外部账号和服务；本机 Webhook/受控模型测试不替代它们。
- 已有隔离真实模型诊断/审批修复及长时压测记录；不据此承诺所有模型都可完成所有业务故障修复。
- 异地密钥托管、另一主机恢复和灾难恢复耗时需由部署者定期演练。本机加密恢复不等于异地灾难恢复。
- 产品定位为单用户管理员工具，不提供多租户隔离或企业 SLA。

早期 QEMU、依赖维护和待办状态保存在 [历史验收记录](audits/2026-11-09-release-checklist-history.md)，不再作为当前状态清单。
