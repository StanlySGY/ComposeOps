# 应用完整备份与异地同步

从导航的“完整备份”进入。支持本地 Linux Docker 节点，远程 SSH/TCP 不会冒用本机目录。生产容器镜像内含执行器代码；开发运行需将 `COMPOSEOPS_RUNNER_IMAGE` 设置为包含当前代码及依赖的镜像。Docker 宿主需支持递归只读 bind mount，执行器使用 GNU tar。

## 创建备份

1. 创建独立的宿主备份目录，在页面保存路径。
2. 选择应用或容器并预检。所选容器所属 Compose 应用的全部容器、Compose/override/env/config/build 引用、bind 文件和目录、命名及匿名卷、固定原镜像、容器可写层均纳入清单。
3. 核对范围、共享写入者、空间和停机影响，单独下载并保管恢复密钥，勾选确认后执行。
4. 独立执行器先保存原镜像，按依赖顺序停写并要求干净退出，归档数据和可写层，反序恢复原运行状态并检查健康。原先停止的容器保持停止。只有产物验证和原应用恢复完成后才生成完成收据。

每个产物使用 AES-256-GCM 加密，保存 SHA256 并解密读回验证。清单同样加密，包含敏感的原始环境与容器配置。下载的恢复密钥是原始 32 字节文件，必须存放在备份介质之外。默认密钥位于数据库旁的 `maintenance/recovery.key`，可用 `MAINTENANCE_KEY_FILE` 指定外置文件；目录通过 `MAINTENANCE_DATA_DIR` 配置。勿丢失或替换已有密钥。

执行与观察连接分离，关闭页面不取消备份。任务和执行器身份持久化，DB v31 的项目锁在面板重启后仍有效。失败或未知结果不会自动重放；按“恢复原运行容器”处理停机日志，复核 Engine、容器配置及原运行范围后才释放互斥。共享挂载的外部写入者、临时数据、无法解析的配置及外部卷驱动会阻断，不以部分备份冒充完整备份。宿主机进程或外部客户端写入仍需由操作者协调。

## 隔离恢复

备份记录中的“隔离恢复”先读取加密清单并校验全部产物，再展示原路径到新目录的映射。选择一个已经存在的具体宿主父目录，确认后创建唯一的 `composeops-restore-<任务ID>` 子目录；目标已存在会拒绝，不能覆盖原数据。

- 所有 bind 和卷数据恢复到新的独立目录，卷在隔离副本中以 bind 方式挂载，不复用生产卷。
- 用可写层快照的不可变镜像 ID 重建，原始镜像归档保留但不会重新打标签影响当前镜像。
- 新建 internal 网络，不发布生产端口、不复制自动重启策略。需要 privileged、宿主命名空间、设备或未备份运行依赖的应用会阻断。
- 默认创建停止的副本；可显式选择启动原先运行的服务，并验证运行/健康状态。结果给出宿主目录、`compose.json` 和容器 ID。
- 恢复前再次验证 Engine、父目录身份、加密清单摘要；归档拒绝路径穿越、越界链接、特殊文件和向链接路径下写入。

这属于文件及应用副本恢复，不自动标记为业务恢复通过。业务数据库原生 dump、SQL 和 HTTP 验收继续使用“可靠性 → 业务恢复演练”。完成验收后可使用结果中的 Compose 文件管理隔离副本；清理时只对该文件执行 `docker compose -f <恢复目录>/compose.json down`，确认不再需要后再删除独立恢复目录。

离线取回后可使用 `node backend/scripts/full-backup-extract.js <备份目录> <恢复密钥> <不存在的新目录>` 验证并解密。它只输出文件，不启动容器。

## WebDAV 与 115

同步目标先保存、授权并进行远端读写测试，测试通过后才能手动上传或开启自动同步。应用恢复运行后再上传，不延长备份停机窗口。只上传完成批次的密文与收据，不上传恢复密钥；同步失败保留本地副本。

WebDAV 使用流式上传、禁止跨域重定向、条件创建和下载 SHA256/长度复验；同名不同内容拒绝覆盖。115 使用自己的开放平台 Client ID、设备码 PKCE 授权、令牌刷新和 OSS 分片上传，并核对网盘返回的 SHA1 与长度。凭据在本地加密存储，不进入概览或明文日志。修改目标后必须重新测试。

115 的 SHA1/长度核验与 WebDAV 下载 SHA256 核验在界面中区分。真实外部账户的授权、服务端配额及公网传输需要实际账户验证；本仓库的协议测试不冒充真实账户验收。恢复时可从目标下载完整批次目录，再使用外置密钥离线解密。

## 可复现验收

`backend/test/maintenance-*.test.js` 覆盖加密篡改、路径/链接、范围、失败后恢复、锁、协议和同步校验。`scripts/fork-improvements-acceptance.mjs` 仅接受独立临时目录与数据库，在候选镜像中验证实际 Docker 备份和隔离恢复，包括命名/匿名卷、可写层、原停止状态及测试 HTTP/Redis 数据。

此实现借鉴 black210/ComposeOps 的 `codex/full-backup-restore` 分支（调研固定 SHA `d39f14dcd5bda9585765a01da5c761dd008d0db5`），并适配主线的节点隔离、授权、持久锁与发布评审。没有引入 fork 的自动纳管或自动整应用更新路径。
