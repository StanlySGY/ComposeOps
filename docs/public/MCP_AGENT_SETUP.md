# MCP 安全接入指南

本文说明如何把 ComposeOps 的运维工具安全接入外部 Agent。ComposeOps 始终负责实际操作和服务端审批。

## 1. 启用前

1. 在 ComposeOps 的「设置 → MCP」中启用 MCP 服务。
2. 默认选择「只读工具」。确认工具清单和纳管范围符合预期后，再考虑切换为包含高风险工具的模式。
3. 复制 MCP Token。把 Token 当作管理员凭据管理，不要放入 Git、截图、工单、提示词或调试日志。
4. 建议让面板仅监听本机，或通过 VPN/Tailscale 与 HTTPS 反向代理访问。不要将单用户管理面板和 MCP Token 直接公开到互联网。

## 2. stdio 客户端模板

将以下配置放入客户端 MCP 配置文件，并替换绝对路径、面板基础 URL 和 Token。COMPOSEOPS_URL 填面板根地址，不要在末尾添加 /mcp；桥接程序会请求 /mcp。

```json
{
  "mcpServers": {
    "composeops": {
      "command": "node",
      "args": ["/absolute/path/to/ComposeOps/mcp/stdio-bridge.mjs"],
      "env": {
        "COMPOSEOPS_URL": "http://127.0.0.1:28765",
        "COMPOSEOPS_TOKEN": "<从 ComposeOps 设置页复制的 MCP Token>"
      }
    }
  }
}
```

如果客户端支持 Streamable HTTP，也可以直接配置面板显示的 HTTP 端点，并通过 Authorization: Bearer <token> 传递 Token。请优先使用面板设置页给出的实际 URL，不要凭默认端口猜测。

## 3. 调用和确认规则

- 先调用工具列表，确认当前暴露的工具范围；只读模式适合日常排障与观测。
- 对需要确认的操作，调用参数中必须显式包含 confirm: true。MCP 是无确认弹窗的通道，未确认时服务端应返回拒绝原因，不应尝试绕过。
- critical 级工具不会经 MCP 暴露。不要把 Token、密码、私钥写入工具描述、会话记录或长期记忆。
- 工具返回状态不等于操作已成功。部署、恢复或其他写操作需要核对服务状态、健康检查或明确的后置条件结果。

## 4. 最小验收清单

1. 在只读模式下确认可以列出允许的状态查询工具，但不能调用测试通知等有外部副作用的工具。
2. 对要求确认的工具，先不传 confirm: true，确认服务器返回拒绝；再通过明确的人工授权流程完成一次非破坏性测试。
3. 故意使用失效 Token，确认请求被拒绝；验证 MCP 响应中的嵌套数据和自由文本已脱敏。
4. 完成连接测试后，确认 Token 不会进入版本库、截图、命令日志或共享配置。

## 安全边界

SQLite 数据库文件当前不提供静态加密。文件权限、磁盘访问控制和备份访问控制有助于降低风险，但不等同于静态加密。独立密钥保管、轮换、备份与灾难恢复闭环明确后，再评估静态加密方案。
