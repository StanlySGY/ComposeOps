# 成员与项目权限

管理员在“设置 → 成员与权限”添加独立账号，选择角色及精确的“节点 + 纳管项目”授权。已有管理员继续使用 `admin` 和原密码登录；原登录会话兼容。新项目默认不授权，命名分组仅整理项目，不传递权限。

| 角色 | 可用能力 |
| --- | --- |
| 管理员 | 全局页面、AI Agent、Shell、节点、配置、成员权限；管理员之间共享全局运维数据 |
| 运维成员 | 仅授权项目的容器状态与脱敏日志，确认后启停或重启现有容器 |
| 只读成员 | 仅授权项目的容器状态与脱敏日志 |

成员登录后直接进入“我的服务”。成员不能使用全局 Agent、Shell、任意 Compose 编辑、Docker API、凭据管理或任意创建容器。项目授权用于应用访问控制，不提供 Docker 内核层多租户隔离。

权限在服务端逐请求、逐资源校验。项目必须仍被纳管，容器 ID 必须精确属于授权项目；写操作复核节点连接版本与容器标签、取得项目互斥、记录审计并核对状态。操作者在网络异常后应先刷新和查日志，不能把请求超时理解为未执行。容器 running 不能替代业务健康验收。

修改角色、授权、启用状态或密码都会撤销该成员的旧登录会话。已连接的全局 WebSocket 同时失效；被降权或停用的管理员发起的持久 Agent 任务会请求停止，无法撤销已经开始的外部副作用。成员自行修改密码仅影响自己的账号。内置管理员不能在成员面板被停用；管理员不能降低自己的当前权限。

服务端拒绝全部未明确开放给成员的全局 REST / WebSocket 路由，包括未来新增路由。`/health` 对未登录用户和成员仅返回存活状态与时间；详细节点健康仅对管理员返回。独立平台监测继续使用 `/healthz/platform/` 的专用凭据。

审计位于 `/api/v1/team/audit`，仅管理员可读；记录账号创建、权限和密码变更、容器操作发起、结果及未知状态，不记录密码原文。权限编辑使用版本号防止覆盖并发修改；离线项目的已有授权会保留并允许手动移除。

## 项目 AI 助手

成员工作台底部新增「项目 AI 助手」。选择已授权项目并提交目标后，任务即持久保存，刷新不终止。只读成员可看状态和脱敏日志；运维成员还可逐次审批现有容器的启动、停止、重启。

任务记录只向发起者开放，使用独立会话，不读取全局记忆和环境快照。工具表没有全局发现、Shell、任意配置、文件和创建容器能力。账号/授权或节点连接变化会阻止后续执行与恢复；旧审批不能再次使用。中断后先核对执行证据，结果未知时记录结论后再继续。
