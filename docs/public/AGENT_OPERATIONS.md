# Agent 驱动运维流程

AI 助手与页面共用节点、纳管、分组、应用目标、接入向导、可靠发布和业务恢复服务。可以在 `/#/agent` 连续完成这些流程，也可以从应用可靠性目标卡片点击“交给 AI 分析与操作”，携带准确的节点、项目、服务、目标 ID 和版本。

## 可以直接提出的任务

- “把公司节点上的 api 项目纳管，关闭 Compose 目录授权，放入我的业务组。”
- “给这个服务配置健康目标，地址是……，HTTP 200，暂不授权自动修复。”
- “评审这两个服务的新镜像……，兼容依据是……；批准前展示变更和回退范围。”
- “按这个业务恢复计划创建备份，然后做隔离 SQL 和 HTTP 验收。”
- “检查刚才的发布结果，只读核对，不重复执行。”

Agent 先发现真实节点和项目，再申请纳管。增量授权不会取消其他项目或离线项目的授权。新 SSH 密码或私钥仍在设置页输入；聊天只引用已保存节点的凭据及其连接版本。

## 审批和执行

高风险写操作保留审批。单服务变更与多服务发布分别校验评审指纹，不能混用；兼容声明、健康地址和数据断言必须来自用户或真实证据。发布依赖现有持久执行器，按依赖顺序更新并逐项验收，仅在预先授权后回退。业务恢复使用独立网络和新卷，不覆盖源数据库。

本会话的持久任务显示于工作台及页面抽屉。刷新后重新读取服务端记录，待完成任务定时更新；点击“查看执行证据”可定位具体记录。备份后启动的恢复演练也显示在原会话中。

- 已排队：提交成功，尚未证明业务可用。
- 备份已校验：只证明备份校验完成，不代表恢复演练通过。
- 接入完成：配置已提交，仍需后续健康观测和恢复演练。
- 业务验收通过：专用执行器满足对应发布或恢复验收条件。
- 需要核对：结果未知或记录不可读取，不自动重放；请核对实际资源。

已开始的聊天工具循环不会因为刷新而自动恢复执行；后台持久任务按原 ID 查询。工具调用成功与业务验收分开记录，未配置独立后置检查的工具不会宣称验收通过。

## 可复现检查

```sh
# 真实模型 + 真实 Agent 工具循环和审批 + 临时数据库；Docker 为合成适配器
node scripts/agent-product-eval.mjs --real-model \
  --config-file=/outside/repo/model.json --report=/tmp/agent-model-report.json

# 独立的真实 Docker 发布与数据库恢复验收
SRE_EVIDENCE_DIR=/tmp/release-evidence node scripts/release-acceptance.mjs --run-isolated-fixtures
SRE_EVIDENCE_DIR=/tmp/recovery-evidence node scripts/business-recovery-drill.mjs --run-isolated-fixtures
```

模型配置包含 `baseUrl`、`apiKey`、`model`，保存在仓库外并限制文件权限。模型评测只发送合成任务，报告记录逐例成败、耗时和 token；供应商未返回费用时保留未知，不估造账单。Docker 演练会创建唯一名称的临时测试资源并在结束时清理。
