# Agent 驱动运维流程

AI 助手与页面共用节点、纳管、分组、应用目标、接入向导、可靠发布和业务恢复服务。可以在 `/#/agent` 连续完成这些流程，也可以从应用可靠性目标卡片点击“交给 AI 分析与操作”，携带准确的节点、项目、服务、目标 ID 和版本。

## 可以直接提出的任务

- “把公司节点上的 api 项目纳管，关闭 Compose 目录授权，放入我的业务组。”
- “给这个服务配置健康目标，地址是……，HTTP 200，暂不授权自动修复。”
- “评审这两个服务的新镜像……，兼容依据是……；批准前展示变更和回退范围。”
- “按这个业务恢复计划创建备份，然后做隔离 SQL 和 HTTP 验收。”
- “检查刚才的发布结果，只读核对，不重复执行。”

Agent 先发现真实节点和项目，再申请纳管。增量授权不会取消其他项目或离线项目的授权。新 SSH 密码或私钥仍在设置页输入；聊天只引用已保存节点的凭据及其连接版本。

## 审批和执行

高风险写操作保留审批。单服务变更与多服务发布分别校验评审指纹，不能混用；兼容声明、健康地址和数据断言必须来自用户或真实证据。发布依赖现有持久执行器，按依赖顺序更新并逐项验收，仅在预先授权后回退。业务恢复使用独立网络和新卷，不覆盖源数据库。

本会话的持久任务显示于工作台及页面抽屉。刷新后重新读取服务端记录，待完成任务定时更新；点击“查看执行证据”可定位具体记录。备份后启动的恢复演练也显示在原会话中。

- 已排队：提交成功，尚未证明业务可用。
- 备份已校验：只证明备份校验完成，不代表恢复演练通过。
- 接入完成：配置已提交，仍需后续健康观测和恢复演练。
- 业务验收通过：专用执行器满足对应发布或恢复验收条件。
- 需要核对：结果未知或记录不可读取，不自动重放；请核对实际资源。

新界面默认创建持久会话任务。刷新、关闭页面或 SSE 断线不会取消服务端执行；“停止任务”才会显式请求停止。刷新后可以在“任务进度与恢复”查看状态并批准原步骤。每个会话同时只有一个正在执行的任务，全局最多 4 个，每次执行最长 30 分钟。

服务重启后不会自动重新执行：任务转为“可继续”或“需要核对”，原审批作废。点击“核对并继续”会重新读取关联发布、恢复及后台操作记录，再开启新的审批门。关联操作仍在执行时不能续跑；结果未知时禁止后续写入。请检查真实资源并记录证据及“已生效 / 未生效 / 已失败”结论。相同任务内已完成的同参数步骤不会再次派发；明确未生效的步骤才可以重新审批执行。

“本轮完成”仅指模型对话轮次结束；后台提交、容器运行、备份校验与业务验收仍分别显示。后台记录缺失、非零命令结果或异常断流不能被当作成功。副作用台账保存脱敏参数、结果和 HMAC 指纹；用量保存数值计数。已开始的 Docker 操作可能无法撤销，停止后必须依据实际资源核对。

旧 API 客户端未传 `durable: true` 时保留旧断线行为。公司成员账号的权限和能力范围见 [成员与项目权限](TEAM_ACCESS.md)。

## 可复现检查

```sh
# 真实模型 + 真实 Agent 工具循环和审批 + 临时数据库；Docker 为合成适配器
node scripts/agent-product-eval.mjs --real-model \
  --config-file=/outside/repo/model.json --report=/tmp/agent-model-report.json

# 真实模型 + 真实 Docker 双服务项目，含纳管分组/单服务操作/健康目标
node scripts/agent-docker-eval.mjs --real-model --run-isolated-fixtures \
  --config-file=/outside/repo/model.json --report=/tmp/agent-docker-report.json

# 持久任务断线、慢客户端、并发持续测试（合成模型，临时 DB）
node scripts/agent-soak.mjs --durable --duration-seconds=900 --workers=4 \
  --requests-per-minute=100 --report-file=/tmp/agent-soak.json

# 独立的真实 Docker 发布与数据库恢复验收
SRE_EVIDENCE_DIR=/tmp/release-evidence node scripts/release-acceptance.mjs --run-isolated-fixtures
SRE_EVIDENCE_DIR=/tmp/recovery-evidence node scripts/business-recovery-drill.mjs --run-isolated-fixtures
```

模型配置包含 `baseUrl`、`apiKey`、`model`，保存在仓库外并限制文件权限。模型评测只发送合成任务，报告记录逐例成败、耗时和 token；供应商未返回费用时保留未知，不估造账单。Docker 演练会创建唯一名称的临时测试资源并在结束时清理。

## 任务预算与上下文

Agent 会先按本轮目标缩小工具目录。需要未显示的能力时，可用 `tool.search` 按中文任务词或工具名搜索，再在下轮调用已加载工具。每次最多加载 5 项，单次任务最多追加 12 项、24000 字节定义；不会下载代码或扩大权限。角色、项目授权、策略拒绝和写操作审批继续生效，成员账号仍使用固定的项目工具目录。

设置 → Agent 策略下可配置新任务的累计预算、单次上下文字节上限、输出上限和请求次数。默认累计 160000 token、输入 64000 字节、输出 4096 token、20 次请求、单条工具结果 8000 字符。每个备用渠道尝试均预留预算；已恢复任务不重置累计数。

供应商未返回用量或调用失败时，用输入 UTF-8 字节加输出上限保守估计，并在任务卡标识。供应商返回有效用量后结算；负数、非数字、缺失的分量不会触发退款，重复完成通知不会重复结算。总量与完整分量之和不一致时采用较大值。预算是调用边界控制：供应商可能报告超额，本次返回后会停止后续工具和请求；金额保持未知。

上下文优先去掉早期历史，再用固定事实摘要替换完整旧工具轮次；当前目标与最新工具调用/结果配对保留。超出上限会停止，不能静默丢掉当前审批或无限扩展上下文。

## 数据生命周期

设置的 AI 历史保留区显示数据库/WAL/可复用空页/磁盘可用容量；既有平台健康负责增长和容量告警。待恢复和结果未知任务的历史受到保护。可选 `docker-compose.archive.yml` 配合外置 `COMPOSEOPS_AGENT_ARCHIVE_DIR`（0700）及外置数据库密钥启用归档；即使没有过期事件，也先检查目录和密钥是否就绪。每批最多 100 条、约 8 MiB，每 6 小时归档一次 90 天前已完成任务事件；单条超过 4 MiB 的异常记录留在数据库，并提示离线处理。归档经过 AES-256-GCM 加密、落盘与解密核对，成功后才删除事件原行。任务结果与副作用证据不会删除。归档文件不会自动删除，需纳入备份及容量管理。

归档面板显示就绪状态、文件数、占用、磁盘可用空间与容量采样时间。目录最多检查 1000 项，缓存 30 秒；扫描不全时明确显示“部分”，不能用作全目录总量。目录失效时仍可暂停自动归档。空批次只表示暂时没有符合条件的事件，不表示已回收数据库文件空间。

离线解密读取可调用 `readRunArchive`，使用同一外置数据库密钥。恢复演练 `npm run recovery:drill -- --backup=/outside/encrypted.db --key-file=/outside/key --report-file=/outside/report.json`，包含成员表和持久任务表完整性与行数核对。


成员真实链路验收（仅唯一临时项目，复核操作员审批、只读成员工具目录和其他容器未变更）：

```sh
node scripts/agent-member-docker-eval.mjs --real-model --run-isolated-fixtures \
  --config-file=/outside/repo/model.json --report=/outside/member-eval.json
```

持续观察可由独立用户服务运行，命令为 `node scripts/agent-long-observation.mjs --hours=24 --output=/outside/observation --health=http://127.0.0.1:28765/health`。合成任务在临时数据库执行，生产仅采样公开健康接口。报告只有完整跑满时长且所有检查合格才为 `passed`，中断及失败都会保留，不会自动续跑并冒充连续观察。大库恢复和压力测试建议分开调度，组合资源争用造成的延迟失败应原样保留。
