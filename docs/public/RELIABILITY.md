# 保留策略、部署评审与历史统计

## AI 历史

设置 → 维护 → AI 历史保留可配置 7–3650 天，默认 90 天。对话、token 用量、Agent 计划与对应执行记录共用 `retention.ai_days`。维护任务在启动一分钟后首次运行，之后每六小时运行；指标采集器不再另行清理 AI 历史。

预览只计数，不删除。早于截止时刻的记录才会删除，边界记录保留。手动清理必须确认已保存期限；期限变化后旧确认会被拒绝。最近成功执行的时间、期限和各表计数持久保存。独立的 Agent 策略审计事件不随计划清理级联删除。

## 完整配置评审

服务项目卡片可直接进入评审或回滚，URL 保留项目、节点及返回列表入口。评审展示按文件顺序合并并解析环境后的 Compose 配置；环境值、构建参数和识别出的敏感值隐藏。

服务器生成 15 分钟有效、一次使用的随机评审凭据。输入指纹只存服务器内存，绑定项目、节点连接信息、工作目录、Compose 文件清单及顺序、文件内容、引用配置、环境文件、相关插值变量与最终有效配置。服务重启或输入变化后需重新评审。部署请求进入队列前和取得项目操作锁后都重新验证，未通过则不启动 Compose。环境保存与 Compose 保存共用项目操作锁。

普通项目操作仍可使用原有入口；只有携带评审凭据的部署属于上述评审流程。宿主检查属于只读请求，完成后不会广播写入刷新。评审展示的是配置快照，外部进程仍可能在最终校验后直接修改宿主文件；它也不锁定可变镜像标签或构建目录内容。实际部署结果需查看退出码和运行状态。移出配置的孤立容器不会由 `up -d` 自动删除。

## 历史指标

原始采样保留七天，七至三十天压缩为五分钟桶，三十天后删除。新桶保留最小值、最大值、总和、样本数与实际覆盖时间；再次合并使用样本权重。图表在 SQLite 内聚合，统计接口直接基于采样及保存的桶统计计算，不再对绘图均值计算峰值。

原始窗口的分位数采用排序位置统计；包含压缩桶时使用按样本数加权的桶均值估计，响应的 `approximation.quantiles` 为真。若窗口边界切入桶，统计包含完整相交桶并标记 `partialWindow` 和 `aggregates`。旧版已压缩数据丢失的峰值与权重无法恢复，v21 将迁移时七天前的已有数据保守标记为 `legacy`，界面会提示近似。

## 加密数据库与备份

普通打开只验证密钥和 schema 可读性，不再每次同步扫描整库。数据库页损坏仍可能在读取相关页时才暴露；全面检查应使用备份或显式验证命令。迁移、恢复验证和密钥轮换保留全面检查。

`node backend/scripts/database-backup.js --source <源库> --output <新备份>` 对源库和快照各执行一次 `integrity_check`，成功后原子发布并设为 0600；不会覆盖已有备份，也不会为备份擅自迁移明文源库。阶段信息写 stderr：打开源库、校验源库、生成快照、校验快照、发布、完成。最终结果 JSON 保持在 stdout。显式校验使用 `--verify <备份>`。加密库仍须通过外部密钥文件提供密钥。

## 验证任务

CI 先执行代码检查、单元测试和构建，再并行运行桌面 Chromium、移动 Chromium、桌面 WebKit、移动 WebKit 的完整测试集。AMD64 与 ARM64 镜像验收保持独立，真实终端搜索测试纳入 AMD64 镜像任务。Pages 仍只在全部 CI 成功后发布同次构建产物。
