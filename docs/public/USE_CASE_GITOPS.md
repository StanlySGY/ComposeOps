# GitOps 自动同步案例

## 场景

Git 仓库中的 Compose 配置发生变更，希望自动同步到运行环境。

---

## 当前实际行为

1. 开发者向配置的远端分支推送提交。
2. Git 平台调用 `POST /api/v1/gitops/webhook/:id`；请求必须携带已配置的 `gitops.webhook_token`，否则 Webhook 保持关闭或返回鉴权失败。
3. ComposeOps 获取远端分支，并将本地工作区切换到仓库配置的分支及其最新提交；手动同步和自动同步使用同一条同步逻辑。
4. 页面可查看提交历史与本地 Git 漂移。回滚会将工作区切到指定提交（detached HEAD）；之后再次同步会重新挂回配置分支。启用自动同步时，下一轮同步会按远端分支恢复版本。

当前 Webhook 直接触发 Git 工作区同步，不会自动调用 Agent 审批，也不会执行 `docker compose up`、重建或重启业务容器。需要部署 Compose 变更时，仍须通过相应项目操作和审批流程执行。

---

## 后续部署闭环边界

Git 仓库同步只保证本地工作树跟随指定提交，不等同于运行环境已经应用该版本。部署、审批和服务健康验证属于独立步骤，不能根据 Webhook 返回成功推断容器已更新。
