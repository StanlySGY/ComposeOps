# 业务数据库和应用恢复

“应用可靠性 → 业务恢复”支持 PostgreSQL、MySQL、MariaDB 的单数据库原生备份及隔离业务演练。该流程与卷归档解包演练分开，只有 SQL 数据断言、连续三次 HTTP 业务检查、RPO/RTO 和资源清理全部通过才显示通过。

## 配置与范围

选择同节点、同应用中的单副本数据库与无挂载无状态应用。数据库、应用及探针镜像固定完整 ID，绑定源容器 ID/创建时间、Docker Engine 身份、节点修订和完整 Compose 输入指纹。源容器或配置变化后需要重新审阅计划。

密码字段填写**源数据库容器的环境变量名称**。凭据仅在执行时读取，不写入计划或结果。暂不支持 `_FILE` 密钥、外部数据库、多库事务及需要文件挂载的应用。应用恢复环境仅使用显式变量与镜像默认值，不复制源容器运行环境；敏感变量使用 `$DB_PASSWORD` 或 `$DB_URL`，其他连接字段可使用 `$DB_HOST`、`$DB_PORT`、`$DB_USER`、`$DB_NAME`。隔离数据库始终使用新随机密码。

SQL 断言只允许业务表记录数与可选单字段相等条件，不接受任意 SQL。建议检查已知业务记录，并让 HTTP 返回中包含实际读取的数据，避免只验证空数据库或存活页。

## 一致性和容量

PostgreSQL 使用 `pg_dump --format=custom`，还原以 `pg_restore --single-transaction --exit-on-error` 执行。MySQL/MariaDB 使用原生 dump 的事务快照，拒绝非 InnoDB 业务表；用户必须确认备份窗口内不进行结构变更。应用层多系统一致性和并发 DDL 不能由单数据库备份证明。

归档经 gzip 解压和退出码检查后原子发布，并记录 SHA-256、字节数与开始时间。备份保存在平台数据库目录下 `backups/business/`，目录 0700、文件 0600。单份原始数据最多 2 GiB，备份前要求至少 2.25 GiB 空余磁盘，每计划保留最近 10 份有效备份；活动演练引用的备份延长保留。静态数据库加密不等于归档加密，归档需由宿主磁盘权限与磁盘加密保护。

## 隔离与失败语义

每次演练在原 Docker 节点创建独立的内部网络、新命名卷和数据库/应用/探针容器；不发布端口，不挂载原应用卷、宿主目录或 Docker socket。容器有 CPU、内存、进程和日志限制。登记资源名称后才创建，退出后按反序核验标签并清理。

RPO 使用备份开始到演练的年龄，RTO 使用演练开始到业务验证完成的耗时。损坏备份、缺凭据、失败断言与超时不算成功。节点或进程中断、Docker 写操作结果未知、清理失败会阻止该计划继续排队，不自动重放。按记录人工核对并清理后，页面允许关闭未知结果；关闭不代表恢复通过。

定时模式需显式授权，最短间隔 24 小时，执行“创建备份 → 固定该备份 → 隔离演练”。暂停或修改计划后，尚未执行的旧版本任务会停止。

## 可复现验收

构建测试镜像：`docker build -t composeops:sre-business-fixture-20261110 scripts/fixtures/sre-business`。

执行 `node scripts/business-recovery-drill.mjs --run-isolated-fixtures`，默认使用 PostgreSQL 与 MariaDB；`SRE_FIXTURE_ENGINES=mysql` 可验证已准备好的 `mysql:8.4`。它只操作唯一测试项目，创建已知数据、备份、隔离恢复、核对源数据前后不变，并验证数据库停止导致 HTTP 503 的遥测关联与恢复。`SRE_EVIDENCE_DIR` 指定证据目录。
