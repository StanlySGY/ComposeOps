# Agent 停止请求归属、状态刷新与预览验收

日期：2026-11-29。生产未重启。前置基线：34bbe11。

## 复现与修复

停止旧任务的请求延迟完成时，原代码会调用当前共享 controller，从而断开已经开始的新任务。先点停止、后收到持久任务编号时，另一条路径只提交停止请求而不释放原连接，并吞掉停止错误。多次点击也会重复提交。

现在停止请求绑定单次运行，串行去重；确认后仅关闭原运行的连接。编号迟到复用同一处理路径。失败保持连接并展示可重试提示，继续保留实际进度，后续队列保持暂停。最终结果到来后移除已过期的停止错误。持久状态事件不代替结束帧，缺少结束确认仍提示核对并禁止自动发送队列。

浏览器恢复闭环还复现了一个公共 API 缺陷：以 `preview`、`check`、`test` 等开头的资源 ID 被路径包含判断误当成只读检查，真实修改后不通知面板刷新。改为只按路径末尾的操作名判定，已有只读校验继续不广播写入。

离线预览增加会话范围的任务/业务操作查询、任务详情及模拟停止和恢复。恢复沿用任务 ID、检查 revision、重新等待审批；已完成任务不重复恢复。全部动作仅作用于内存中的示例数据，刷新后清空，未接触真实 Docker/模型/生产任务。
