# ComposeOps 导航、功能与 UI/UX 复查（2026-11-05）

本轮接续 `d2e4701`，目标是把已有能力串成连贯的操作路径，并扩大真实功能验证。保留中文、暗色工作台和状态色体系，通过实际操作找到问题后修复。第一轮架构与配置安全审查见 [设计与交互审查](2026-11-05-design-ux.md)。

## 设计结论

Vue、Fastify、SQLite 单体符合个人运维场景，Compose 文件仍是配置事实来源，显式纳管与审批、备份、审计是值得继续保持的基础。当前主要短板是功能入口较多，但跨页上下文、目标状态和异步反馈还不完全统一。本轮优先补齐这些具体断点。

视觉上采用紧凑的位置导航、清楚的当前页、局部筛选标签和轻微悬停反馈，避免再增加一层大型装饰卡片。返回操作始终可见，手机只保留必要文字；等待超过 180ms 才显示页面加载进度，支持系统减少动画设置。服务健康分数改为信息展示，避免呈现一个实际上没有动作的按钮。

## 已修复的问题

| 问题 | 修复结果 |
| --- | --- |
| 多个页面进入后缺少明确返回路径，局部返回不一致 | 全局位置栏提供返回、前进、面包屑和页面标题；优先恢复真实历史及原始查询条件；直接打开页面时返回父页面；拒绝未知和外部来源 |
| 从配置或日志返回时容易丢失来源 | 保留原筛选、展开、滚动和日志上下文；直接进入日志支持 `from=services/topology`；草稿确认取消后仍能再次导航 |
| 手机更多功能遗漏 Compose，功能多时不好找 | 补齐入口、中文与别名搜索、无匹配反馈、当前功能高亮；命令面板补齐长期任务 |
| 终端切换下拉框后标签变了，但旧容器会话仍在 | 切换项目、容器、Shell、同页深链或节点立即断开；显式点击连接才建立新会话；连接栏显示目标和状态；迟到请求不会恢复旧节点会话 |
| 终端信息失败后缺少恢复入口 | 区分加载、失败、未启用、未连接和连接中状态，提供重试；离页销毁终端及资源 |
| 长期任务离开再返回丢失选中项和标签页；交错详情请求可能显示错任务 | 选中任务和标签页记录到 URL；恢复相同位置；详情响应绑定当前任务和请求代次；等待时不显示上一任务内容 |
| 服务收藏保存失败仍显示已收藏，并产生未处理异常 | 请求成功后才更新状态；保存中防重复点击；失败提示并允许重试；补充 `aria-pressed` |
| 服务筛选结果不清楚、卡片样式缺少挂载类 | 可独立移除搜索/状态筛选，一键清空；结果数量有读屏状态；恢复已有卡片悬停与焦点样式 |
| 自定义模板创建/编辑返回 `{"template":{}}` | 修正 Fastify 响应 schema，返回 ID、名称、Compose、变量定义与时间字段，新增创建→编辑→搜索→删除接口回归 |
| 设置页初始慢请求覆盖用户刚修改的偏好 | 偏好独立加载，读取成功前禁止编辑/保存默认值；读取失败显示局部重试；其他面板慢加载不再覆盖偏好 |
| 离线预览缺少长期任务响应，巡检示例等级字段不一致 | 补齐空任务与 worker 状态响应，修正巡检示例为真实后端使用的 `attention/findings` 语义 |

## 测试结果与实际操作

- 前端：**461 项通过，73 个文件**。
- 后端：**495 项通过，1 项按原环境条件跳过**；串行执行，使用独立测试数据库。
- 桌面/手机 Playwright：**48 项通过，4 项按视口条件跳过**。包含主页面巡检、历史返回/前进、来源回退、草稿取消、筛选、收藏失败重试、手机功能搜索、焦点循环、键盘标签页和 320px 窄屏。
- ESLint、生产构建、预览构建、`git diff --check` 通过。

真实浏览器使用本地生产构建、独立 SQLite 和一次性两服务 Alpine Compose 项目。通过真实后端/文件/Docker 验证：

1. 登录；偏好保存后刷新仍保留，恢复原值。
2. 可视化修改一个 Compose 环境变量，语义校验、变更预览、确认保存、磁盘核对、历史备份比较；运行容器仍保持原值，证实仅保存不重启。
3. `.env` 表格修改、仅保存、自动备份、恢复历史版本、关闭弹窗；直接核对文件恢复原值。
4. 服务进入真实日志，搜索、暂停/恢复、下载、返回原项目并保留展开。
5. 真实终端执行无副作用命令；切换到另一容器后验证旧 WebSocket 关闭、未自动创建新连接；显式连接后在新容器执行并收到输出。
6. 自定义模板创建、检查响应字段、编辑、收藏、搜索、查看、删除。
7. 定时任务创建、停用、启用、删除；没有执行任务。
8. 工作流创建、编辑、删除；没有启动工作流。
9. 长期任务创建、更新状态、报告标签页→执行态势→返回，确认恢复同一任务和标签页；测试任务最后取消。

真实测试启动 `buildApp()`，不启动定时调度和后台执行器。测试只修改一次性项目及独立数据库，不更改生产业务容器。测试中的选择器歧义、错误 HTTP 方法拦截和编辑器冷加载等待均在复测前纠正；最终结果没有把失败用例计为通过。

## 发布与边界

发布使用 `docker-compose.yml` 与 `docker-compose.encrypted.yml`，保留 `0.0.0.0:28765:3001`、`composeops_opsdash-data` 和外置只读加密密钥挂载。发布前保留当前镜像回滚标签与在线加密数据库快照，并对候选镜像验证升级、认证、重启持久化、备份恢复、静态文件及生产快照完整性。

这轮没有调用付费 AI、发送通知、操作真实远程 SSH/TCP 主机或运行生产破坏性操作。AI 与远程节点的接口/单测覆盖不能替代真实外部服务验收。长时间压力测试也不在本轮范围内。

仍需单独设计的架构问题：后端当前活动节点是全局状态，多客户端并发不能只依赖前端保护；大型页面/数据库模块值得按领域拆分；部分加载错误仍需统一与空态区分。它们涉及更广的状态模型和兼容性，应作为独立改造验证。本轮已补齐可复现的导航、目标混淆、保存反馈和慢加载问题，没有将这些改进描述为消除了全部潜在缺陷。
