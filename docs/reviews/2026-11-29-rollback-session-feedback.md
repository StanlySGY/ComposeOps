# 回滚中心的反馈与请求归属（2026-11-29）

## 已复现的问题

- GitOps 历史请求完成前不打开窗口，用户看不到加载反馈；关闭或身份变化后迟到的历史仍可出现。
- 回滚确认框提交后立即关闭，错误落到历史窗口后面的页面，重试丢失确认目标；成功也没有说明工作区与运行容器的区别。
- 配置恢复完成后无上下文检查，切换节点后旧请求仍会刷新新节点；旧请求的 finally 还能结束新请求的忙碌状态。
- GitOps 列表、历史和回滚绕过统一 API 客户端，没有统一的身份归属、401 和写入缓存失效处理。

新增首轮 5 个回归在原实现下全部失败，保留原始日志。

## 修复

GitOps 请求使用现有统一 API，历史读取增加取消信号。窗口立即显示加载态、错误可原位重试，关闭后取消读取并忽略迟到结果。确认时复制仓库目标，执行期间禁用重复提交与关闭，失败保留目标并在确认框中显示错误；成功显示可聚焦的反馈和项目入口，明确工作区已回滚、运行容器尚未应用配置。

配置、卷、升级配置和 GitOps 恢复的回调绑定当前页面与节点上下文。失活、退出或切换节点会使旧回调失效，旧请求不能刷新新节点或清理新操作状态。本人密码轮换仍保留项目选择并恢复读取。前端不重放写请求，不宣称关闭页面已撤销后端恢复操作。
