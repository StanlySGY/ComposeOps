# 身份状态重读与共享缓存归属（2026-11-29）

`auth.check()` 会更新当前账号和角色，但之前只在登录、退出、失效入口推进共享请求的身份版本。状态重读发现账号改变、角色降级、会话变为未登录或连接失败时，旧账号的缓存和已发请求仍属于旧版本，存在晚结果复活的缺口。

本次在有效身份变化或丢失已确认身份时推进同一身份版本，复用已有共享 Store 清理与请求失效机制。同账号、同角色的正常重读及显示名变化不会清空当前上下文，不新增轮询、请求或服务端权限策略。

验证：新增 5 场景中 4 个修复前失败，正常身份重读场景始终通过；修复后相关 59 项单测通过。登录/退出、旧缓存隔离、隐藏页面连接和密码轮换保留节点的 16 项浏览器回归通过，lint、预览与生产构建通过。日志保存在 `~/.local/state/composeops/overnight-20261128/auth-recheck-*`。
