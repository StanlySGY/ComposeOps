# 引号凭据与流式脱敏边界复核

日期：2026-11-29。基线：8fd9c9e。本轮仅修复脱敏解析和验证，不部署或重启生产。

## 实际问题

- 带空格的 `PASSWORD="fictional alpha beta"` 只遮住第一段，后半段仍会出现在自由文本中。
- JSON 转义引号、单引号转义和多行字符串可能提前结束匹配；Basic Authorization 未被自由文本规则覆盖。
- 流式输出的赋值头与值分开发送后，尾部会丢失脱敏上下文；JSON 键与冒号之间换行也需要保留。
- 已知完整凭据包含 `TOKEN=...` 时，先按片段遮蔽会破坏后续完整值匹配；在截断前必须完成值级替换。

基线复现只使用虚构数据。最初新增的 16 项测试全部失败，原始失败日志保留。

## 修改

统一赋值扫描器供文本遮蔽、敏感值收集、流式尾部持回使用。扫描完整引号值，处理反斜线、连续单引号、换行以及 Authorization；重复脱敏保持幂等。收集 JSON 解码值以保护其再次出现在自然语言中的情况。完整已知值先替换，再做静态形态和键值脱敏。

未闭合值、未确定的键名和跨分片引号保持持回；最终结束时保守遮蔽秘密前缀。空 env 赋值不吞掉下一行普通设置。保留既有值收集上限（4–400 字符、300 个值、2MB 输入）和文本 12K 上限；不声称支持任意语法、任意大小秘密或完整 DLP。

参考 RFC 8259 第 2/7 节的 JSON 空白与转义规则，以及 Docker Compose 的 env 文件引号/多行语法。在线搜索工具未返回可用内容，官方页面通过直接 HTTP 下载核对，保存在本地证据目录的 `rfc8259.html` 和 `docker-env-interpolation.html`。
