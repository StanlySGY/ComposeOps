# 多节点资产图谱与血缘树（2026-11-29）

## 已验证缺陷

原图谱把所有项目连到活动宿主或第一台宿主；同名卷使用名称作 key，跨主机会合并。容器关系用 project:name 猜资产 ID，实际 ID 不同则丢失关系。节点复制到视图局部状态后，资产更新或退出登录不能及时清除旧名称。台账模式没有读取告警和巡检，却显示为 0 与“暂无活动告警”；ForceGraph 还会把项目/宿主实体数当作“正常”。

嵌入资产中心时整个工具栏被隐藏，用户无法切换已有血缘树；树中每台主机重复展示全部项目，存在容器就被视为运行。没有项目时即使存在主机和卷也显示空图。9 条组件回归全部在原实现失败。

## 改动

以实际资产 ID 和 hostId 派生图谱，按关系读取容器及挂载，过滤跨节点错误关系，项目与自己的宿主连接，同名卷独立显示。快照直接派生自共享 store，身份清空和同步结果立即反映到图谱。图谱显示当前快照实体，不将未采集数据当作健康结论。

恢复嵌入工具栏的图谱/血缘树切换、刷新与失败重试；树按宿主分组并展示真实项目状态，未载入宿主的项目归入明确的未知归属分组。进入服务的深链保留 hostId、项目定位和 CMDB 来源，能够先切到对应节点再查看服务。离开资产中心时不再让其他路由的查询参数重置图谱页签，返回保留血缘树。父子缓存页面都配对管理刷新监听。

## 验证

相关 40 项单测通过，前端全量 1335 项通过；随后修复的离页页签保留由浏览器覆盖。根 lint、预览和生产构建分别检查独立退出码，均通过。

最终 16 个浏览器组合全部通过（Chromium/WebKit × 桌面/移动端）：同名卷、快照健康语义、节点分组、跨节点定位与返回、读取失败原位重试、缓存页重新读取、320px 工具与树布局。窄屏截图经目视检查。

首轮浏览器 12 通过、4 失败，先发现测试把现有返回按钮误当链接；修正选择器并隔离演示 WebSocket 数据后，第二轮又发现真实的离页重置问题以及移动端应使用浏览历史返回按钮。均保存原始 trace/错误上下文，最终实现和断言共同验证返回时血缘树仍在，没有用重试掩盖产品错误。
