## 问题与取舍

管理员和成员任务面板的列表已有请求代次保护，但详情、审批和人工核对没有完整的操作归属保护：切换会话、项目或离开缓存页面后，旧请求可以重开详情、写入旧错误、清掉新操作的忙碌状态。核对流程还会在 await 之后读取可变的 detail.run.id，关闭弹窗时可访问空对象，切换任务时可读取错误记录。重复表单提交缺少函数入口防重入，成员任务提交完成会覆盖其间新输入的草稿。

这轮改善已有持久任务的使用可靠性，没有增加 Agent 工具、数据库迁移或运行依赖。

检索工具未返回可用搜索结果，Context7 返回 fetch failed；随后直接读取 Vue、MDN 和 MCP 官方页面，均 HTTP 200。原始 HTML 和摘要保存在仓库外验收目录。采用 Vue 生命周期配对、失效请求清理和 Page Visibility API；已支持的 Vue 3.5 能满足需求，无需升级框架。读取的 MCP Tasks 2025-11-25 页面仍标注 experimental，不把该版本页面等同于全网最新版本，也不据此替换现有审批、恢复与副作用核对。

## 改动

- 三个任务面板共用 `useAgentTaskPanel`。列表读取与用户操作有独立代次，只有当前上下文仍有效时才能更新界面；KeepAlive 失活、卸载与上下文切换清理监听、定时器和读取请求。
- 详情和核对固定任务 ID、证据内容与详情代次。关闭弹窗取消后续读取、清空表单；已经发出的写操作不自动取消或重放。函数入口同步防重入，旧操作不能释放新操作的 busy 状态。
- 操作错误与读取错误分开保存，后台读取成功不会抹去操作失败。业务任务面板首次读取失败也能自动恢复，不依赖尚未读到的 running 状态。
- 标签页隐藏时停止列表轮询和数据变更触发的读取，返回立即刷新。进行中及等待后台结果的任务每 3 秒刷新，静止任务每 30 秒刷新；业务运维记录保持原有 5 秒/完成后停止逻辑，读取失败 5 秒重试。
- 成员任务提交成功仅清理仍等于已提交内容的草稿；选择范围或授权项目变化后，旧任务响应不写入新范围。管理员任务允许 checkpoint 缺失时使用默认文案。
