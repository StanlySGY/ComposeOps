# CMDB 同步完整性与节点隔离（2026-11-29）

## 问题与修复

原同步吞掉项目、卷、网络扫描错误，把异常解释为空列表并记录成功；项目扫描之后才再次获取活动节点 Docker 客户端，切节点可能把另一台机器的卷写到原节点名下。落库没有事务，中途失败可留下半份资产。没有整体读取期限，也没有同节点并发同步协调。

同步现在在开始时固定 host ID、连接修订和 Docker 客户端，所有来源均读取同一节点；允许用户切换界面节点，但连接修改或删除会拒绝旧快照。项目、卷和网络完整读取并验证后才开启同步写事务。读取失败、HTTP 200 中的卷驱动 Warnings、格式异常和整体超时都明确报错，保留既有台账；取消信号传递给 transport，迟到完成不能写库。失败审计记录真实失败。

同节点同连接修订的并发调用共享一次完整快照；不同节点独立执行，连接更新后不复用旧请求，旧请求清理也不能移除新请求归属。资产和关系写入原子提交，中途数据库失败回滚整批。

## 官方依据

实时获取 Docker Engine API v1.51 官方规范，VolumeListResponse 的 Warnings 字段明确描述读取卷列表时的警告；因此不能把 HTTP 200 一律当作完整快照。已核对当前安装 dockerode 5.0.1 的 listVolumes/listNetworks 均向 transport 传递 abortSignal。

- https://docs.docker.com/reference/api/engine/version/v1.51.yaml
- SQLite 事务保证参考 https://sqlite.org/lang_transaction.html
