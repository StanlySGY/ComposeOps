# 指标整理写锁竞争修复（2026-11-29）

## 生产观测与可复现缺陷

保留原 24 小时观测：截至 04:25，健康检查累计 5 次失败，其中 03:20 为超时。只读检查生产日志发现从 11 月 28 日 18:20 到 29 日 04:20，每小时约 20 分均有任务 Worker 或平台监测的 `database is locked`。指标整理每小时执行，生产库约 4.69GB（不含 WAL）。时间相关性吻合，但未替换生产版本，因此不宣称已完成生产因果验证或消除健康失败。

代码中 `compactMetrics` 在历史范围扫描前执行 `BEGIN IMMEDIATE`，并在整个聚合查询期间占用唯一写锁。即使历史已经全部聚合、没有任何需要修改的桶，也会阻塞其他连接写入。两个独立 SQLite 连接的 3 条回归均可复现：平台心跳写入受阻、无操作整理仍阻塞、扫描后新增样本无法进入。

## 修复

候选发现采用只读扫描，每次最多 500 个桶；真正写入每批最多 32 个桶，约 25ms 后主动结束当前批次（单桶 SQL 与 COMMIT 不能抢占，故不是严格耗时上限）。获取写锁后重新读取每个窄时间桶，再原子更新聚合值并删除原样本，避免发现与提交之间新增样本造成统计丢失。批次间留 5ms 调度间隔，过期删除每批 500 条。无需整理的系列不启动写事务。

SQLite 官方 WAL 文档说明同一时刻仅有一个写者；事务文档说明 BEGIN IMMEDIATE 立即取得写事务。已实时获取：
- https://sqlite.org/wal.html
- https://sqlite.org/lang_transaction.html

## 大样本验证

独立加密临时库，6 个交错写入的系列，共 1,800,000 条样本、12,000 个桶，前台另一个连接每 5ms 写一次心跳；前台 busy_timeout 为 5 秒。

| 项目 | 原实现 | 最终实现 |
| --- | ---: | ---: |
| 总整理时间 | 23.758 秒 | 24.127 秒 |
| 最长单次持写锁 | 1684.18ms | 141.73ms |
| 前台最长写入等待 | 1132.08ms | 133.18ms |
| 前台成功写入 | 1687 | 2875 |
| 前台锁超时 | 0 | 0 |
| 保留桶 / 样本数 / 数值总和 | 12000 / 1800000 / 134100000 | 完全一致 |

第一版把候选发现窗口也缩至 32，虽然减少锁等待，但总耗时增至 55.36 秒；该结果和原始日志保留，最终调整只读窗口后回到上述性能。这是本机合成基准，不保证生产任意规模和冷缓存的耗时。

相关 32 项测试通过，最终加密库 18 项通过，覆盖跨节点、重复整理幂等、失败回滚、并发新增样本与多批次统计。后端全量 1299 通过、1 跳过、0 失败，后端 lint 通过。无生产数据库修改、清理或重启。
