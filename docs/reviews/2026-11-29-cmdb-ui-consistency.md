# 资产中心读取与交互一致性（2026-11-29）

## 已复现问题

资产同步只刷新 assets、不刷新 relations；删除没有失效在途请求，旧读取可能恢复已删除资产/关系或覆盖新错误；SWR 使手动刷新返回旧缓存并吞掉新的读取失败。同步后的刷新错误被吞掉，界面可能误报完整成功。确认框在删除请求完成前关闭，失败后目标丢失、缺少忙碌锁；缓存页面离开后未清理 Teleport 确认框。

首批 7 条 store 回归中 5 条失败、2 条通过。复查又补充并发手动刷新覆盖同步读取结果的用例，先失败再修复。失败日志均保留。

## 改动

- 同步完整刷新资产与关系；删除成功后失效旧请求并同步移除关联边；读取失败保留原数据。
- 清单/拓扑 API 等待实际刷新结果并暴露错误。写入后读取失败明确说明操作已经执行，只需重新读取；错误归属于自身请求，不依赖可能被其他请求清空的共享 error。
- 删除确认保留目标、提交时锁定、错误原位重试；说明删除的是台账记录与关联关系，Docker 资源保留。
- 页面离开、身份变化、节点变化和页签变化使旧确认与反馈失效。缓存页返回重新加载。
- 区分读取中、真实空清单、类型筛选无结果和读取失败；筛选空态引导查看全部，显示当前最多 500 项资产/500 条关系的范围。

Vue 官方 KeepAlive 文档已核对激活/失活生命周期： https://vuejs.org/guide/built-ins/keep-alive.html 。未新增定时任务或生产请求。
