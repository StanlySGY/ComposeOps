# 共享缓存与登录身份边界（2026-11-29）

## 复现

原有请求客户端会拒绝旧身份的 HTTP 响应，但 Pinia store 的生命周期长于页面，退出登录并不销毁这些 store。浏览器中先读取项目/工作流，再退出、登录另一身份，并让新身份的读取返回 503，仍会显示旧账号的 4 个项目和 1 个工作流。失败截图与 trace 保留。

额外复现：首次进入服务页时延迟项目读取，切到总览后释放响应，隐藏的服务页仍会创建一条容器 WebSocket。连接错误处理还可能在旧 socket 关闭后重启轮询。

## 修复

- 服务、节点、项目分组、工作流、资产、事件、AI 配置七个共享 store 订阅身份变化；同步清除旧列表、错误、时间和节点选择，并使在途读取失效。
- 旧写入完成后不能借用新登录态继续刷新或广播；旧事件更新、节点探测的 finally 只清理自己登记的请求，不能删掉同 ID 的新请求。
- store 销毁时注销监听并清理实时资源。旧连接错误的归属按连接与版本双重判断，关闭前先失效，涵盖同步 close 回调。
- 服务页首次加载每次 await 后检查页面激活版本，离开后不能开启实时连接；返回页面正常恢复。
- 本人修改密码只轮换凭据，保留已确认的节点和缓存，旧凭据请求仍失效。退出、登录或会话失效则清空所有身份数据。

没有更改服务器权限模型或持久任务执行；客户端身份隔离不替代后端鉴权。

## 验收

- 最初 5 项核心回归全部失败；扩展测试继续发现其他 store 的残留，原始失败日志保留。
- 相关 store 与视图 61 项通过；最终前端全量 162 文件、1266 项通过；lint 通过。
- Chromium/WebKit 桌面与手机相关浏览器矩阵 180 项通过，包含退出再登录、读取失败不显示旧缓存、首次加载离开及返回恢复。
- 凭据轮换 42 项针对性单测通过；最终构建后的专用浏览器 16 项全部通过，覆盖 Chromium/WebKit 桌面与手机。生产构建与预览构建通过。
- 测试用 Pinia action 包装后的 Promise 不能用引用相同判断去重，改为断言实际请求次数及两个调用均收到结果；该失败也保留。

参考官方 Pinia v4 文档/实现的 setup store effect scope、$dispose 和 disposePinia：卸载组件不会销毁 store，计时器需要显式释放，作用域清理使用 Vue onScopeDispose。通过 Context7 获取并对照当前 Pinia 4.0.3 的 API。
