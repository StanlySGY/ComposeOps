# Agent 长期记忆边界修复（2026-11-29）

## 复现问题

1. 去重查询读取 `scope_id`，分组却使用不存在的 `scopeId`，导致同类型不同项目的同内容记忆被误合并。
2. 合并只累加召回次数，丢失被删除记录更近的召回时间；同时把更新时间改成维护时刻，使长期未用的重复记忆凭空变新。
3. 排序把显式 `importance = 0` 当成默认 0.5，抬高低优先级事实。
4. SQLite UTC 时间交给无时区的 `Date.parse`，宿主时区不同会改变新鲜度分数。
5. 近期更新的旧事实仍可能被旧召回时间触发衰减，或仅因较早创建而清理。
6. 保存后的返回值来自模糊搜索第一名，可能返回另一条重要度更高的相似键记录。

独立库 6 条初始回归全部失败，日志保留；没有对生产记忆执行维护或清理。

## 修复

按作用域、作用域 ID 与内容的精确元组分组；合并保留最早创建、最近内容更新、最近召回和累加召回次数。维护不冒充用户更新；衰减要求内容更新和最近召回均超过期限，清理要求创建和内容更新均超过期限。零重要度正确参与排序，SQLite 无偏移时间统一按 UTC 解释；保存后按全局作用域和精确键查询返回记录。返回字段与既有分数公式保持兼容，无数据库迁移。

SQLite 官方日期文档明确日期函数使用 UTC，已实时获取核对：https://www.sqlite.org/lang_datefunc.html 。这是修正现有存储语义，不引入新记忆框架或自动清理策略。
