## 设计与实施顺序

1. **读取稳定性与最小工作区权限**。现有 Compose/env 读取复用可写目录、Docker socket、默认网络的执行器；同宿主浏览器已记录辅助容器网卡连断时的 `ERR_NETWORK_CHANGED`。新增与执行器分开的只读工作区（只读目录、无 socket、无外网），读取按节点和权限模式缓存；启动失败必须回收。真实执行保留原网络能力。API 仅对 GET 的瞬时网络异常进行一次有取消、节点上下文约束的延迟恢复，HTTP 错误和写入不能自动重放。
2. **环境变量编辑完整性**。检查文件族、读取、并发保存、恢复与编辑器草稿。代码目前说明支持 `.env.production`，实际正则却不接受；Compose 保存已有版本校验，env 保存未提供同等的用户草稿冲突保护。统一合法文件族，给编辑器增加读取版本与冲突反馈，验证 mounted/workspace/SSH 路径及符号链接边界。
3. **监控可信度与生命周期**。复核节点切换、配置变更、采样失败、过期历史和页面隐藏/恢复。已发现节点采集失败分支缺少配置身份复核，以及切换至“全部节点”时历史请求可能未失效。改进目标是让迟到数据不能覆盖新范围，过期读数和采集错误明确可见。
4. **实际使用路径复核**。使用桌面与手机浏览器巡检总览→服务→日志/配置→纳管/分组；检查空态、失败重试、筛选清除、深链、键盘焦点及长列表。只实施有证据的问题，延续既有中文暗色视觉体系。
5. **持续验收与发布**。专项测试覆盖失败路径，完成全量前后端测试、lint、构建；隔离测试环境进行持续导航/请求稳定性验证。发版采用原四份 Compose 配置、外置密钥与原数据卷，验证健康、源码版本和其它容器状态，留下备份与回退记录。

## 约束

- 分组用于单用户整理，不赋予多用户访问隔离；不改变 Agent 审批或自动恢复授权。
- 网络恢复不能掩盖持续错误，不重放写入；取消或节点切换后不得发起旧请求的第二次尝试。
- 真实业务容器不用于破坏性测试，未知操作结果禁止自动重做。
- 保留现有备份；不以删除数据或放宽验收标准换取通过。
