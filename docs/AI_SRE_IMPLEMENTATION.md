# AI SRE 升级：第一阶段

目标：面向自托管应用的 AI 自主运维平台。持续观察、受控执行、验证结果。

本阶段交付可靠 AI 值守员的完整故障恢复闭环；后续再扩展有界自治、可靠升级和恢复演练，不以聊天界面改名代替升级。

## 本阶段实现

- 独立于通知开关的只读值守，检查已纳管项目；按节点、项目、容器归并故障，重启不丢失事件。
- 保存脱敏的状态、日志、观测时间和身份信息；AI 基于证据给出假设，证据不足明确展示，不能替代验收。
- 每个故障复用长期任务、授权快照、Effect 执行账本和审计。首个版本化处置流程为“单容器重启并验证”，其他情况保留人工处理入口。
- 处置固定节点、Docker Engine、项目、容器完整 ID 和创建时间；审批后仍检查授权有效期、拒绝策略、项目锁和目标身份。每个故障最多派发一次该动作。
- 执行中断或通信结果不明时不重试写操作；继续只读观测并要求核对结果。
- 连续三次健康观测且持续至少 30 秒才能标记恢复；无 HEALTHCHECK 只证明进程存活，明确展示验证范围。观测失败、目标替换、健康检查未恢复不能报告成功。
- AI 值守页面聚合故障、审批、证据、恢复进展及历史，可跳转现有任务/日志/Agent；总览提供入口。页面失活释放轮询，恢复后刷新。
