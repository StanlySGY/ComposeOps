# 体验改进验收 · 2026-11-27

本轮落实体验检查中的六项问题，不增加图片素材或更换现有视觉体系。

## 已实现

1. **页面发现**：侧栏与快速跳转共用页面定义。完整备份、应用可靠性、AI 值守均可按名称搜索，保留历史指标、设置子页和动态项目操作。工单名称统一，仍支持“长期任务”别名。
2. **运行意图**：每个项目可标注未标注、预期运行、计划停机、维护中，保存在数据库并按项目的节点身份隔离。总览、简报、服务筛选与卡片共用判断；正常停止或维护既不算健康运行，也不会仅因停止算故障。非零退出码、OOM、健康失败、重启循环等证据仍需关注。整体启停明确成功后记录预期状态，失败和未知结果不改写；维护标记和操作期间用户修改的意图保留。新建并部署项目记为预期运行，失败后仍可发现并处理。
3. **手机操作**：设置分类条自动展示选中项，增加完整分类选择器；监听与页面激活/失活配对。添加节点按钮不再被压成多行。新建 Compose 的正文独立滚动，底部提交操作保持可见。
4. **创建反馈**：实时提示名称、根目录、空 YAML 与大小限制，禁用按钮附近显示首个未满足条件。大写名称提供显式转换建议。保留关闭重开草稿、持久任务与未知结果防重复提交逻辑。
5. **服务密度**：默认收起项目，按节点记忆展开项；支持全部收起及深链定位展开。展开后隐藏重复快捷栏，单容器只保留一组日志、终端、诊断入口，服务与容器操作范围仍清晰。
6. **设置草稿**：偏好、通用 AI、通知和更新策略提供未保存状态与撤销；汇总渠道、密码和纳管草稿，点击提示可定位分类。有草稿时保护刷新/关闭，站内切换继续保留；渠道组件缓存保留撤销快照，密钥只在内存中保存。
