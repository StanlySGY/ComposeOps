# 需求

## 目标

根据 2026-09-26 全项目审查结果，完整处理 P1 可靠性问题与已确认的 P2 契约、体验和扩展性问题，并为关键竞态和资源清理补充回归测试。

## 本轮范围

- WebSocket Shell 在 `container.exec()` / `exec.start()` / stream error 失败时释放会话槽位。
- Agent `compose.exec` 超时时关闭输出流并终止/停止实际 exec，避免请求失败后命令继续运行。
- 工作流取消不被完成/失败覆盖；condition 节点支持兼容现有顺序 nodes JSON 的 true/false 跳过语义；编辑器可配置可执行节点参数。
- 数据卷备份恢复、下载、删除按备份记录宿主执行，不依赖当前活动节点。
- 修正 `volume.mount` 前置检查与工具参数契约。
- 实时 Shell/Agent 页面不被 keep-alive 保活。
- 远程 Compose 凭据传递和蓝图宿主可见性先做安全边界修正；无法在无远程 Docker 环境下证明的部分必须增加失败保护和测试替身，不伪造端到端验证。
- 自定义模板 YAML 校验、社区市场未接入状态、CMDB 卷/网络同步、指标保留调度。
- 监控时间窗口与阈值边界、删除不一致的死 API、节点切换后的缓存刷新和实时页面生命周期。
- 导航分组、指标采集保护、路由大 chunk 预取策略和 CMDB 分页/上限保护。

## 非目标

- 本轮不接入新的外部社区模板源；会修正其空实现的产品契约和 UI 状态。
- 不重做 CMDB 数据模型，但补齐已有承诺的 volume/network 资产同步并增加查询上限保护。
- 不改变指标采集的核心数据模型，但修正保留调度和采集压力保护。
- 不引入多用户 RBAC，不改变单用户产品边界。
- 不把敏感 SSH 密码或私钥直接写入普通 Compose 子进程环境或日志。
